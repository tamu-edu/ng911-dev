# Test Description: TD_CHFE_019

## Overview

### Summary

Refer-To header field

### Description

This test verifies Refer-To header field in SIP REFER message generated by the CHFE:
- if contains "serviceurn" parameter with URN of "urn:service:sos", "urn:service:test:sos", "urn:emergency:service:sos" or their subservices
- if its value is a valid SIP URI


### References

* Requirements : RQ_CHFE_281, RQ_CHFE_044, RQ_CHFE_045, RQ_CHFE_047
* Test Case    : TC_CHFE_019

### Requirements

Implementation eXtra Information for Testing (IXIT) config file for CHFE.

### SIP/HTTP transport types

Test can be performed with 2 different SIP/HTTP transport types. Steps describing actions for a specific transport are marked as follows:

- (TLS) - should be used by default
- (TCP) - used in the lab for testing purposes only if default TLS is not possible

## Test Sequence

### Test Preamble

#### Test System ESRP

* Install Wireshark[^2].
* Copy the TD-specific SIP Service scenario `ESRP_CHFE_019.xml` to local storage.
* (TLS v1.2) Configure Wireshark to decode SIP over TLS, use tests system and FE certificate keys [^3]
* (TLS v1.3) Configure logging of session keys and configure Wireshark to decode SIP over TLS [^4]
* Start packet capture on the interface connected to CHFE:
  * (TLS)

    `ip.addr == IF_ESRP_CHFE_IP_ADDRESS and tls`

  * (TCP)

    `ip.addr == IF_ESRP_CHFE_IP_ADDRESS and sip`

#### Test System ECRF-LVF (Variation 3)
* Copy following LoST response files to local storage:
  ```
  findServiceResponse.xml
  ```
* Install Wireshark[^2]
* Install OpenSSL v1.1.1 or higher[^5]
* (TLS v1.2) Configure Wireshark to decode HTTP over TLS, use test system and CHFE certificate keys[^3]
* (TLS v1.3) Configure logging of session keys and configure Wireshark to decode HTTP over TLS[^4]
* Using Wireshark on 'Test System ECRF-LVF' start packet tracing on IF_ECRF-LVF_CHFE interface - run following filter:
   * (TLS)
     > ip.addr == IF_ECRF-LVF_CHFE_IP_ADDRESS and tls
   * (TCP)
     > ip.addr == IF_ECRF-LVF_CHFE_IP_ADDRESS and http
* Run HTTP server acting as ECRF-LVF (LoST server) for Variation 3:
  * (TLS)
  ```
  python3 http_entry.py --ip IF_ECRF-LVF_CHFE_IP_ADDRESS --port 4443 --role RECEIVER --path /lost --method POST --body_file findServiceResponse.xml --content_type application/lost+xml --response_code 200 --server_cert test_system.crt --server_key test_system.key
  ```
  * (TCP)
  ```
  python3 http_entry.py --ip IF_ECRF-LVF_CHFE_IP_ADDRESS --port 8080 --role RECEIVER --path /lost --method POST --body_file findServiceResponse.xml --content_type application/lost+xml --response_code 200
  ```


### Test Body

#### Variation
1. SIP URI transfer target
2. E.164 telephone number transfer target
3. Transfer target is a PSAP assigned to location provided manually

#### Stimulus

1. On Test System ESRP run custom SIP service using following command (replace names in {} with values):
  * (TLS transport)
    >   sudo python3 test_suite/services/stub_server/sip_service/sip_entry.py \
  --scenario test_suite/test_files/SIPp_scenarios/sip_service/CHFE_019/ESRP_CHFE_019.xml \
  --scenario-type auto --bind-ip {IF_ESRP_CHFE_IP} --bind-port 5061 \
  --remote-ip {IF_CHFE_ESRP_IP} --remote-port 5061 \
  --tls-cert {ESRP_CERT_FILE_PATH} --tls_key {ESRP_KEY_FILE_PATH} \
  --tls-ca {PCA_CERT_FILE_PATH} \
  --protocol TLS
  * (TCP transport)
    >   sudo python3 test_suite/services/stub_server/sip_service/sip_entry.py \
  --scenario test_suite/test_files/SIPp_scenarios/sip_service/CHFE_019/ESRP_CHFE_019.xml \
  --scenario-type auto --bind-ip {IF_ESRP_CHFE_IP} --bind-port 5060 \
  --remote-ip {IF_CHFE_ESRP_IP} --remote-port 5060 \
  --protocol TCP

2. On CHFE, answer the incoming test call.
3. On CHFE, manually initiate a call transfer to one of the following targets:
   * Variation 1 - any SIP URI e.g. `sip:psap@chfe-2.ng911.example`
   * Variation 2 - any E.164 telephone number e.g. `+16502389205`
   * Variation 3 - enter the location of a transfer target to trigger LoST query (to find target's SIP URI)
4. Confirm the transfer, if the CHFE requires confirmation.

#### Response

Using the decoded SIP traffic captured between CHFE and Test System ESRP, identify the SIP REFER generated by CHFE for the active test dialog as a result of the transfer stimulus.
For all variations the identified SIP REFER verify that:
* exactly one `Refer-To` header field is present;
* the URI in the `Refer-To` header field is a SIP URI, i.e. its scheme is `sip`(case-insensitive);
* a `tel` URI, `urn` or any other URI scheme is NOT acceptable.
* the `Refer-To` header field contains exactly one `serviceurn` header parameter;
* the `serviceurn` value is a quoted string;
* the value of the `serviceurn` starts with one of the following patterns, any subservices are allowed (e.g. sos.ambulance, sos.animal-control, sos.fire, sos.gas, sos.marine, sos.mountain, sos.physician, sos.poison, sos.police):
  * `urn:service:sos` 
  * `urn:service:test.sos`
  * `urn:emergency:service`

VERDICT:

* ERROR - Test System ESRP fails to send stimulus
* PASSED -  if all checks passed
* FAILED - any other cases

#### Examples

Examples of valid Refer-To header fields:
```
Refer-To: <sip:chfe2@chfe2.test.example>;serviceurn="urn:service:sos.ambulance"
Refer-To: <sip:chfe@chfe.test.example:5060>;serviceurn="urn:emergency:service:responder.police"
Refer-To: <sip:+12025551212@chfe.test.example>;user=phone;serviceurn="urn:service:test.sos.animal-control"
```
Examples of NON-acceptable Refer-To header fields:

`Refer-To: <tel:+12025551212>;serviceurn="urn:service:sos"` - tel URI

`Refer-To: <sip:chfe2@chfe2.test.example> ` - no servicerun

`Refer-To: <sip:chfe2@chfe2.test.example>;serviceurn="urn:service:sos";serviceurn="urn:service:responder.police"` - duplicated serviceurn

`Refer-To: <sip:chfe2@chfe2.test.example>;serviceurn="urn:service:counseling"`- wrong urn
